# GCP-1202 Console Control-Plane PoC Manifests

This directory contains a scrubbed snapshot of the hand-applied manifests used to run the console control-plane-side during the GCP-1202 spike (proof-of-concept demonstration of running the OpenShift console in the control plane). It serves as evidence and a reproduction aid for the spike, NOT a proposed production deliverable. The production implementation will use a CPOv2 console component plus the ported dual-API console-operator — see ../operator-migration.md for details.

## Directory Layout

| Directory | Contents |
|-----------|----------|
| `console/` | Control-plane console and downloads operand manifests. Three-layer kustomize structure: `origin/` (verbatim upstream openshift/console-operator static assets), `hypershift/` (generic control-plane overlay with no console-operator), and `example-overlay/` (per-HostedCluster values). |
| `guest/` | Resources applied to the guest (hosted) cluster's kube-API: ConsoleCLIDownload CR, ClusterRoleBinding for OIDC identities, and firewall workaround script. |
| `hostedcluster/` | HostedCluster, NodePool, namespace, Certificate, and pull-secret for the demo cluster. |
| `.gitignore` | Guards against committing credentials (kubeconfigs, OAuth secrets, signing keys, session keys). |

## SECRETS

**Every credential was deliberately excluded from this copy.** Nothing in this tree may ever hold a real credential. The `.gitignore` file guards against re-adding them.

A reproducer must supply the following secrets:

- **HostedCluster ServiceAccount signing key** (`hostedcluster/sa-signing-key.yaml`) — must match the published JWKS at the infraID's OIDC bucket path
- **Google OAuth client secret JSON** (`guest/oauth_client_secret.json`) — the intact OAuth 2.0 web application client credentials file
- **OpenShift pull secret** (`hostedcluster/pull-secret.json`) — registry credentials for pulling OCP images
- **Management cluster kubeconfig** — for applying console manifests to the HCP namespace
- **Guest cluster kubeconfig** — for applying guest-side resources
- **Session keys** (generated by `console/example-overlay/apply.sh`):
  - `.session-encryption-key` (32 bytes) — AES encryption key for OIDC session cookies
  - `.session-authentication-key` (64 bytes) — HMAC authentication key for OIDC session cookies

## PLACEHOLDERS

Environment-specific values were replaced with grep-able tokens and must be swapped before use:

- **User/tag tokens**: `REPLACE_USER`, `REPLACE_TAG`, `REPLACE_CONSOLE_OIDC_CLIENT`
- **Example identifiers**: `console-demo`, `console-demo-a1b2.us-c1-e5d4c3-1.dev.gcp-hcp.openshiftapps.com`, `example-hcp-customer`, `condemo-a1b2`, `123456789012`

Before applying, grep for `REPLACE_` and for the example domain `console-demo-a1b2` to find all placeholders that need substitution.

## Order of Operations

To reproduce the PoC:

1. **Apply hostedcluster resources** (against the management cluster):
   ```bash
   cd hostedcluster/
   # Supply sa-signing-key.yaml and pull-secret.json first
   kubectl apply -f namespace.yaml
   kubectl apply -f pull-secret.yaml
   kubectl apply -f sa-signing-key.yaml
   kubectl apply -f certificate.yaml
   kubectl apply -f hostedcluster.yaml
   kubectl apply -f nodepool.yaml
   ```

2. **Wait for the control plane** to become available (monitor HostedCluster conditions and HCP pods).

3. **Apply console manifests** (against the management cluster):
   ```bash
   cd console/example-overlay/
   # Supply ../../guest/oauth_client_secret.json first
   KUBECONFIG=/path/to/management-kubeconfig ./apply.sh
   ```

4. **Apply guest resources** (against the guest cluster):
   ```bash
   cd guest/
   # Supply guest kubeconfig via KUBECONFIG environment variable
   KUBECONFIG=/path/to/guest-kubeconfig ./apply.sh
   KUBECONFIG=/path/to/guest-kubeconfig kubectl apply -f redhat-domain-admins.yaml
   # Run firewall workaround if needed (updates GCP firewall rules)
   ./allow-geneve-firewall.sh
   ```

## Custom Images

The PoC required custom-built console and control-plane-operator images carrying the upstream patches listed in ../upstream-changes.md:

- **Console image**: Patched bridge binary with off-cluster TLS trust fixes (`-ca-file` and `-service-ca-file` support) and OIDC refresh token support (`access_type=offline` + `prompt=consent`)
- **Control-plane-operator image**: Stock CPO for the konnectivity-socks5-proxy and token-minter sidecars

This requirement disappears once those upstream PRs merge and ship in a release payload.

See `console/README.md` for detailed documentation of the console layer structure and control-plane adaptations.
